# 手勢動畫修整第一輪（2026-11-07）

這次修改實際由手勢觸發的 Unity 動畫，不只調整 Blender 展示姿勢。手勢 1–5、辨識門檻、校正、冷卻時間、語音與手部映射設定維持不變。

## 動作修改

| 手勢 | 俠客 | 琴師 |
| --- | --- | --- |
| 1／行禮 | 降低彎腰與低頭幅度，頭先略轉再跟隨身體行禮 | 抱琴行禮的低頭稍晚於身體，保留小幅轉向互動 |
| 2／賞景 | 頭先看向指引方向，再由手臂跟上 | 慢奏曲線維持原設計 |
| 3／飲酒 | 延長舉起接近嘴部的過程，頭部稍晚跟上，提早開始收回 | 停琴回應維持原設計 |
| 4／戒備 | 手部目標下移，手肘略收，錯開上臂與前臂的起動，延長收勢 | 縮小邀請手勢的外伸幅度，放慢展手 |
| 5／出招 | 修正為左手持劍，改成蓄勢、一次揮出、收勢；軀幹先帶動 | 急奏起手的兩種軌跡連續混合，縮小手腕與身體的過度擺幅 |

出招的 Hybrid 遮罩改成軀幹、頭、左臂；右臂仍可由手部映射控制。純映射模式與待機設定沒有修改。互動目前是動畫內的小幅轉向，不是持續追蹤另一個角色的視線系統。

## 重建與證據

- `GestureAnimationRefinement.Rebuild`：重建 5 段俠客、8 段琴師動畫，保留原資產 GUID；檢查旋轉曲線、數值有效性、左手出招及兩個 Hybrid 場景遮罩。
- 修改前逐格與數值記錄：`../motion-review/`；修改後：本資料夾的 `MotionReview.json`、五張動作分鏡及單張截圖。
- `HybridHandoffValidation.Run`：60 組交接斷言通過，涵蓋兩角色、五動作、30/60/120 FPS、自然結束及中途取消，並在收尾時反轉手部目標。
- `HybridTheatreValidation.Run`：首次功能斷言全部通過，但搜尋索引啟動例外使整體報告失敗。後續已修正背景測試過早進入 Play Mode 的啟動順序，三套驗證重跑均無此例外；本目錄 JSON 已更新。原錯誤與修正證據保留在 `../editor-startup-fix/`，亦驗證了刻意注入錯誤時會正確判定失敗。
- 本機 WebGL 已重建成功；GitHub、Docker 未發布。
- `HybridBrowserValidation.json`：新版真實 WebGL 的單／雙人混合模式，事件去重、忙碌略過、出招時右臂持續操控、最新目標交接、暫停及重設通過。
- `Browser.json`：六種單／雙人模式、桌面與手機尺寸的載入及暫停恢復通過；映射與混合模式的模擬移動通過。測試使用獨立 5089 服務與假攝影機，已停止該測試服務。

同樣的 60 Hz 模擬輸入下，俠客出招手腕速度尖峰由約 2.77 降至 1.41 m/s；琴師急奏動作期間的最大關節角速度由約 629 降至 353 度/秒。這些是軌跡指標，不等於動作自然度評分。仍需後續操作測試，確認使用者想要的演出力度、持劍方向與琴弦接觸效果。
